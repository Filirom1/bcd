# Implementation Plan: Circulation History — Pagination and Performance

**Branch**: `007-circulation-history` | **Date**: 2026-03-26 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/007-circulation-history/spec.md`

---

## Summary

The existing borrower and item circulation history views are silently truncated (last 20 and last 10 records respectively), making them untrustworthy for long-running libraries. This plan extends both existing history endpoints with server-side pagination (page/page_size) and date range filtering (date_from/date_to), adds a missing database index on `return_date`, activates the stub item history tab in the catalog record detail view, and updates both history UI tabs to call the dedicated history endpoints with pagination controls. All new user-facing text is added to both `en.json` and `fr.json`.

---

**Testing**: pytest, service-layer integration tests (AAA pattern)
**Target Platform**: Linux + Windows
**Performance Goals**: History page load < 2 seconds on 5+ year old hardware (dual-core 2GHz, 4GB RAM); response time must not degrade with 10,000+ total transactions
**Constraints**: No npm/build tools for web UI; vanilla JS + Vue 3 Composition API only; legacy hardware must remain responsive
**Scale/Scope**: Single elementary school; expected max ~500 records per borrower over 5 years, ~100 records per popular item

## Phase 0: Research

**Status: Complete** — see [`research.md`](research.md)

**Key decisions made:**

1. **Offset-based pagination** — compatible with existing `Pagination.js` component, sufficient for expected data volumes
2. **Sort order `checkout_date DESC`** — corrects current `return_date DESC` to match spec and enable consistent date filter application
3. **BorrowerDetail calls dedicated history endpoint** — avoids reloading full borrower detail on each page navigation
4. **`return_date` index via Alembic migration** — resolves the only missing index needed for this feature
5. **Total count always included** — required by `Pagination.js`, acceptable overhead at school-library scale

### 1.3 Service Layer Changes

File: `src/bcd_api/services/circulation_service.py`

**`get_borrower_circulation_history()` — extended signature:**
```python
def get_borrower_circulation_history(
    db: Session,
    borrower_id: str,
    page: int = 1,
    page_size: int = 20,
    date_from: Optional[date] = None,
    date_to: Optional[date] = None,
) -> BorrowerHistoryResponse:
```

Logic changes:
- Filter: `return_date IS NOT NULL` (completed only — consistent with spec)
- Apply `date_from`/`date_to` on `checkout_date` when provided
- Run `COUNT(*)` on filtered query for `total_items`
- Apply `.order_by(checkout_date.desc()).offset((page-1)*page_size).limit(page_size)`
- Return structured `BorrowerHistoryResponse` (replaces unstructured dict)
- Remove the embedded `current_loans` field from this response (those come from the Current Loans tab, separate endpoint)

**`get_item_circulation_history()` — extended signature:**
```python
def get_item_circulation_history(
    db: Session,
    item_id: str,
    page: int = 1,
    page_size: int = 20,
    date_from: Optional[date] = None,
    date_to: Optional[date] = None,
) -> ItemHistoryResponse:
```

Logic changes:
- Fetch `current_loan` separately (`return_date IS NULL`) — not affected by date filter, not paginated
- Completed history query: `return_date IS NOT NULL` + optional date filters + pagination
- Sort: `checkout_date DESC`
- Return structured `ItemHistoryResponse`

### 1.5 Web UI Changes

**BorrowerDetail.js — History tab**

Current behavior: loads `circulation_history` from borrower detail endpoint response.
New behavior:
- History tab is **lazy-loaded** — API call made when user clicks the History tab (not on modal open)
- Calls `GET /api/v1/circulation/borrower/{id}/history?page=1&page_size=20` on first open
- Date filter inputs (From / To) trigger a new API call with `page=1` and date params
- Pagination events from `Pagination.js` trigger API call with new `page` number
- Reactive state: `historyPage`, `historyDateFrom`, `historyDateTo`, `historyPagination`, `historyItems`, `historyLoading`
- Remove: loading `circulationHistory.value = data.circulation_history` from borrower detail load

**RecordDetail.js — History tab (implement from stub)**

Replace placeholder alert with:
- On tab activation: call `GET /api/v1/circulation/item/{item_id}/history?page=1&page_size=20`
- Show `current_loan` banner (if not null) using `info` Bootstrap alert: "Currently on loan to {name} — Due: {date}"
- Date filter inputs (From / To) above history table
- Paginated history table: columns — Borrower, Checkout, Return, Status
- `Pagination.js` component for navigation
- Empty state: `circulation.no_history` or `circulation.no_history_for_period` (if date filter active)
